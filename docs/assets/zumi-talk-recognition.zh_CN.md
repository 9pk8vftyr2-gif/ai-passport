# Talk 录音、发音与恢复

2026-10-18。仅修改电脑端，没有实体设备操作。此前的
[人设验收](zumi-talk-persona.zh_CN.md)保留为历史快照。

## 本次变化

- 浏览器提示麦克风准备中、可以说话、音量过轻/过响、麦克风关闭。仍需按 OK 才录音，
  进入页面不开麦；权限拒绝和迟到授权均安全停止。音量提示是近似判断，不是校准仪表。
- 继续请求回声消除、降噪与自动增益，优先使用浏览器原生 16 kHz 重采样，增加 70 Hz
  高通和 7 kHz 低通。小缓冲 worklet 保留重采样回退。这是采集链路调整，不代表已经
  测得真人识别率提升。
- 按 OK 发送时先排空最后一个不完整 PCM 帧，再提交；最多补齐一个 20 ms 帧。排空
  最长 500 ms，退出或打断会取消；迟到回调不能提交已放弃的轮次。
- 官方 Zumi 人设已要求品牌统一输出为 `Z C O`，按三个英文字母读；中文优先称呼
  “祖米”。明确的绿色生活语境中，对“减碳”的可能同音误识别做简短确认与解释，不对
  不明确的词强行替换。
- 当前检查到的控制台选项没有 ASR 热词表。人设影响理解与朗读，不是修改识别解码器。
  页面保留服务端原始识别，不用显示层替换来掩盖识别错误。
- 正常完成后复用当前云端会话，支持承接上文；打断先发 abort 再关闭，出错、退出、
  断线和空闲超时也会清理。打断后的新会话隔离旧语音，此时不保证保留此前上下文。
  官方长期 Memory 仍关闭；平台留存规则是另一回事。

## 实测结果

[测试记录](talk-v1/recognition-recovery.json)分开记录原始识别、理解、传输和用户验收。
自动测试均使用合成语音，代理没有开启用户的真实麦克风。

| 项目 | 实际观察 |
| --- | --- |
| 品牌输出 | 回答文本按 `Z C O` 输出；控制台保存与回读一致 |
| 祖米原始识别 | 测试轮次中正确识别中文名 |
| ZCO 原始识别 | 首次专名测试有错字，恢复后的提问识别正确 |
| 减碳原始识别 | 仍被识别为“检叹”，**尚不能证明识别率提高** |
| 当前会话追问 | 正确记得上一轮谈的是骑自行车出门 |
| 云端打断 | 中断长故事后，新一轮网站游戏问答完整返回 |
| 浏览器连续流程 | 两轮完整问答、一次打断、一次恢复后完整问答；四次开麦的音轨全部关闭 |
| 音频边界 | 接收 495 块、播放 486 块，打断主动丢弃 9 块；队列最大 12、观测断流 0 |
| 麦克风生命周期 | 模拟媒体通过权限拒绝、迟到授权关闭、失焦取消、尾帧先于提交发送 |
| Worklet | 16/44.1/48 kHz 帧边界、尾部采样保留和结束顺序通过 |

首次专名测试后进一步补充了同音词语境规则，但没有据此把失败的原始识别结果改记为通过。
新增 `tests/test_talk_worklet.cjs`，并扩展 `tests/browser_talk_microphone.cjs`、
`tests/test_xiaozhi_relay.py` 和需显式启用的 `tests/browser_xiaozhi_live.cjs`。
默认检查流程不会调用云服务。
